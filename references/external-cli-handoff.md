# External CLI File Handoff Contract

Extracted verbatim from SKILL.md for Phase 1 coverage audit; SKILL.md retains the original until Phase 2.

## External CLI File Handoff Contract
- External LLM reviews are runner-neutral. `config/ai_model_registry.json` declares runners, route-qualified model ids, aliases, quota groups, default reviewers, quota-error patterns, and fallback policy.
- Write the full request into a Markdown handoff file first instead of passing the full prompt as a shell argument.
- Structure request handoff files as metadata plus `Why`, `What`, `How`, `Where`, `Verify`, then payload.
- Pass only a short instruction and the absolute handoff file path to the CLI; do not stream the full request body on stdin by default because the Markdown file is the durable handoff contract.
- The bash command itself must name an explicit absolute command-output path through stdout redirection or `--output-format text`; a path mentioned only inside the prompt is not enough.
- The wrapper may sanitize that raw command output into the durable Markdown response file and delete the raw capture; treat ambiguous model claims such as "saved to the plan file" as invalid unless the claimed path equals the command-level output or sanitized response path.
- agy runner routes invoke `agy --approval-mode plan --output-format text --include-directories <project-root> -m <cli_model> -p <prompt>`. Direct Claude Code routes invoke `claude -p <prompt> --model <cli_model> --no-session-persistence --tools "" --add-dir <project-root>`.
- In approved runner environments, direct external CLI invocation is the primary path. In Codex app sessions, if the platform blocks private workspace egress after explicit user approval, classify it as `platform_permission_blocked` and move execution to the approved external-review runner rather than trying UI or terminal workarounds.
- If the user approved the exact external CLI step but the runtime still routes the escalation through an automatic guardian reviewer and blocks private workspace egress, classify it as `platform_permission_blocked`: do not keep retrying, do not drive Terminal UI as an indirect workaround, and ask the user to switch the thread/workspace permission mode so escalation prompts go to the user approval path.
- When a Shadow v2 close gate is tracking that condition, record the blocked route with the runner route and reason, for example `--blocked-review external_cli:agy=platform_permission_blocked`, so downstream reports preserve the permission-mode remediation.
- Use the manual handoff route only as a last-resort fallback when the platform permission mode cannot be changed and the user explicitly accepts user-operated CLI execution: run `run_external_plan_reviews.sh` with `--manual-handoff-only`, show the generated `*.manual-command.md` files to the user, have the user run those commands directly in their own terminal, then rerun the wrapper with `--ingest-manual-responses` to redact, parse, write reports, and generate provenance.
- For ad-hoc implementation-review packets that contain diffs or source excerpts, prefer an inline-only packet that does not ask the external CLI to inspect filesystem paths. If filesystem inspection is intentionally required, include the project root via `--include-directories`.
- External CLI review must use `risk_preflight_status: approved` with concrete `approval_ref`, exact `approved_next_step`, and main-thread `risk_preflight_recorded_by`; `pass` is not enough because the call crosses an external-service boundary.
- Capture CLI stdout into a redacted Markdown response file before parsing or normalizing it into `docs/report/`; request parser-compatible bullet fields when downstream automation depends on fixed response fields, but preserve malformed sanitized stdout for retry diagnostics.
- After parsing an external CLI response successfully, write a wrapper-generated `*.provenance.md` manifest beside the response file with evaluator runner, requested/actual route, requested/actual CLI model, quota_fallback_triggered, verdict, request file, response file, response hash, command-response path, `raw_capture_deleted: true`, and `sanitized_response: true`.
- Keep durable handoff artifacts under project docs, preferably `docs/orchestration/<task-id>/external-cli/<plan-version>/<round>/`, so long prompts and raw responses survive shell argument limits and are easy to inspect.
- Treat local external-review provenance as consistency evidence, not tamper-proof attestation. In a writable workspace, a human can forge matching response/request/provenance files; if tamper resistance is required, stop for an external signing or audit mechanism instead of accepting local files.
- Do not put raw secrets in handoff or response files; redact sensitive values before writing durable Markdown artifacts.
- **Quota fallback**: `run_external_plan_reviews.sh` and `external_review_runner.py` load aliases, runner routes, quota groups, default reviewers, quota-error patterns, and phase-aware fallback rules from `config/ai_model_registry.json` or `CODEGUIDE_MODEL_REGISTRY`. Automatic fallback is allowed only when the exhausted registered route has an explicit `fallback_policy` rule for the current task phase; unregistered or unconfigured exhausted routes fail closed.
