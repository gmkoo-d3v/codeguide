2. 조기 종료 파이프: 가장 위험한 형태는 조용한 통과SIGPIPE under set -o pipefail

3. 기본 테스트가 실제 agy를 실행하지 않게실제 CLI 호출 문제

  • 이전 통합 작업의 트립와이어 로그에는 agy models 한 줄이 있었습니다. 기존 테스트 하나(bundled agy routes use catalog cli_model values)가 agy가 PATH에 있으면 실제로 agy models를 실행했고, 전체 스위트에서 실제 CLI를 건드린 유일한 곳이었습니다.
  • 이제 정적 레지스트리 맵 검증은 항상 실행하고, 실제 카탈로그와의 비교는 CODEGUIDE_LIVE_AGY_CATALOG=1일 때만 실행합니다. 건너뛴 사실은 TAP에 # skip으로 남습니다.
  • 선택 실행 경로 자체도 mock agy로 검증했습니다. 모든 모델이 있는 목록에서는 통과하고, 등록된 모델이 하나 빠진 목록에서는 실패합니다.
  • 이는 자동 검사 하나를 선택 실행으로 옮긴 것입니다. 기본 실행에서 실제 카탈로그와의 대조가 사라졌으므로, 모델을 갱신할 때는 사람이 한 번 켜서 확인해야 합니다.

7. 남은 것과 한계

  • 무작위 SIGPIPE 경쟁 자체는 재현하지 못했습니다(2절). 대용량 단위 테스트와 정적 검사로 막았을 뿐입니다.
  • 기준선 실패 2건(done 작업의 이전 계획 버전 평가 보고서, JSON 이슈 id)은 원인을 조사하지 않았습니다.
  • Shadow v2 close 게이트는 새 해시를 검사하지 않고, 증거는 여전히 위조 가능한 일관성 증거입니다.
  • 하네스를 거치지 않는 작업, 에이전트가 쓰는 리뷰 요구 필드, 완료된 작업의 승인 이력은 이전과 같이 게이트 밖에 있습니다(KL-3~5).
  • Gemini 4 Argon과 역할 라우팅 문서·에이전트 프리셋은 사용자 결정이 필요합니다.
